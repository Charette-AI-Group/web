Version 1.0.0

Released 6 August 2026 · Windows and macOS

The first public release, and a complete one on Windows. CloakClip replaced a pair of personal PowerShell scripts, and it stays wire-compatible with them — text cloaked by the old scripts still uncloaks here, and the test proving it in both directions is a permanent part of the test suite rather than something checked once.

Two ways to work

  • Clipboard tab — copy text, click Cloak Clipboard, paste the result anywhere. The box is editable, so a message can be uncloaked, reworded and re-cloaked without the plain text ever leaving the app
  • Manual tab — a plain field and an encrypted field that stay in sync as you type, with no buttons for either direction. Reading a message this way never touches the clipboard at all

Keeping secrets out of clipboard history

The feature that took the most work, and the reason the app exists rather than a script.

  • Decrypted text placed on the clipboard is marked secret using the same mechanism password managers use, so Windows keeps it out of the Win+V panel and out of cloud sync — while it still pastes normally
  • Text you cloak is tracked too, because whatever app you copied it from had already recorded it before CloakClip ever saw it
  • A copy made again by hand is detected, re-protected, and the recorded entry removed
  • Closing the app clears a copied secret and sweeps the session's secrets from history; Clear All! empties everything as a deliberate second line of defence

The limits are stated in the app as plainly as the features: matching only recognises exact text from the current session, and nothing can reach a secret that has already been pasted somewhere else.

Passwords and comfort

  • A password menu holding the last ten, each shown only as its first and last character (h…!), stored encrypted with Windows DPAPI under %APPDATA%\CloakClip\ and clearable at any time
  • A password is remembered only after it actually works, so a typo is never kept
  • Light and dark themes following Windows by default, a window that reopens where you left it, and a single-file executable with nothing to install

Platform support

Windows is fully supported. macOS builds and runs, and encrypts and decrypts identically — but its clipboard protections are not implemented yet, and the app reports them as unavailable rather than pretending. Nowhere does it claim a protection it cannot provide; where a platform cannot do something, it says so.

How this build was checked

  • 123 automated tests, and a clean lint, before anything is built
  • Windows and macOS builds are produced by CI from a committed build specification, so a release is never assembled by hand on somebody's desk
  • Every build runs its own self-test before it is uploaded. A packaged application can silently lose a bundled component and still start, looking perfectly healthy while a whole protection is missing; the self-test reports what the build actually contains, and CI refuses to publish one that comes up short

Keeping up with releases

Every version is published on GitHub with its binaries attached, and this page is updated alongside. If you would rather be told than check, GitHub's Watch → Custom → Releases on the repository will email you when a new one appears.
